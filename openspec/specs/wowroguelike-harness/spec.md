# Wowroguelike-harness Specification

> Generated by openlore v1.2.0 on 2026-11-13 21:19

## Purpose

Provides CLI entrypoint and simulation harness capabilities for running single encounter demos,
batch statistical runs, and party composition balance analyses.

## Requirements

> `src/WowRoguelike.Harness/Program.fs`

### Requirement: Demo

The system SHALL executes a single encounter simulation with the scripted party and prints the outcome, full combat log, and final world dump.

#### Scenario: RunScriptedEncounterDemo
- **GIVEN** A seed and maximum tick limit
- **WHEN** demo is invoked
- **THEN** The harness SHALL execute the encounter via Bench.runEncounter and print the tick count, outcome,
full combat log, and final world state to stdout

### Requirement: Runs

The system SHALL executes batch encounter simulations across multiple sequential seeds and reports aggregate outcome metrics.

#### Scenario: AggregateEncounterOutcomesAcrossSeeds
- **GIVEN** A run count n and maximum tick duration
- **WHEN** runs is invoked
- **THEN** The harness SHALL simulate all n seeds, tally cleared, wiped, and unresolved encounters, and output
summary metrics including median, minimum, and maximum tick counts

### Requirement: Comps

The system SHALL simulates party compositions across dungeon wings and seeds to measure class throughput, survival rate, and resource pool sustainability.

#### Scenario: EvaluatePartyCompositionPerformance
- **GIVEN** A seed count and an optional character level override
- **WHEN** comps is invoked
- **THEN** The harness SHALL simulate Scarlet Monastery wings with distinct healer and DPS roster permutations,
measuring clear rates, party survival, and remaining resource pools

### Requirement: Usage

The system SHALL displays available simulation subcommands, flags, and parameter formats to the user.

#### Scenario: DisplayHarnessUsageHelp
- **GIVEN** A command-line request for help or invalid input parameters
- **WHEN** usage is invoked
- **THEN** The harness SHALL output the list of supported CLI commands and usage instructions to stdout

### Requirement: RunSimulation

The system SHALL the harness shall parse cli arguments, execute headless game simulation scenarios across core rules and story progression, and return an execution status code.

#### Scenario: SuccessfulHeadlessSimulationExecution
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** Valid command-line arguments and initialized core and story components
- **WHEN** The simulation harness entry point is invoked
- **THEN** The simulation executes headlessly and returns an exit code of 0

#### Scenario: SimulationExecutionWithInvalidParameters
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** Invalid, unrecognized, or missing command-line arguments
- **WHEN** The simulation harness entry point is invoked
- **THEN** The harness outputs error information to stderr and returns a non-zero exit code
