# Wowroguelike-harness Specification

> Generated by openlore v1.2.0 on 2026-10-13 11:07

## Purpose

Provides the headless CLI simulation harness for executing encounter runs, golden replay
fingerprinting, performance benchmarking, pathfinding diagnostics, and dungeon floorplan generation.

## Requirements

> `src/WowRoguelike.Harness/Program.fs`

### Requirement: Main

The system SHALL parse command-line arguments and route execution to the requested simulation, benchmarking, diagnostic, or dungeon command.

#### Scenario: RecognizedCLICommandExecution
- **GIVEN** A valid command identifier such as 'demo', 'bench', 'runs', 'dungeon', 'fingerprint', 'diagnose', or
'profile'
- **WHEN** The program is invoked with the command arguments
- **THEN** The corresponding handler SHALL execute and the process MUST exit with code 0

#### Scenario: UnrecognizedCommandArguments
- **GIVEN** Invalid or unrecognized CLI arguments
- **WHEN** The program is invoked with the invalid arguments
- **THEN** CLI usage guidelines SHALL be printed to standard output and the process MUST exit with code 1

### Requirement: Demo

The system SHALL simulate an encounter for a given seed up to a maximum tick threshold and print the outcome, combat log, and final world state.

#### Scenario: ExecuteScriptedEncounterDemo
- **GIVEN** A target random seed and maxTicks count
- **WHEN** demo is invoked
- **THEN** The simulation SHALL run up to maxTicks and the encounter outcome, combat log, and final world state
MUST be written to standard output

### Requirement: Runs

The system SHALL simulate a batch of encounters across n seeds and print aggregate outcome statistics including cleared, wiped, unresolved counts, and tick distributions.

#### Scenario: BatchSimulationSummary
- **GIVEN** A total number of seeds n and a maximum tick limit
- **WHEN** runs is invoked
- **THEN** All n encounters SHALL be simulated and summary statistics (cleared count, wiped count, unresolved
count, median/min/max ticks) MUST be output to standard output

### Requirement: Bench

The system SHALL benchmark tick loop execution times across multiple seeds, synthetic entity counts, concave geometries, search algorithm comparisons, and heap sizes.

#### Scenario: RunPerformanceBenchmarks
- **GIVEN** A request to benchmark the simulation engine
- **WHEN** bench is invoked
- **THEN** Performance metrics for fight split costs, synthetic entity scaling (100, 250, 500 hostiles),
concave maps, search comparisons, and priority heap scaling SHALL be measured and printed

### Requirement: Fingerprint

The system SHALL generate and output canonical state text of an encounter simulation for deterministic golden-replay verification.

#### Scenario: CanonicalFingerprintGeneration
- **GIVEN** A seed and maxTicks limit
- **WHEN** The fingerprint command is executed
- **THEN** The encounter SHALL be simulated and the canonical fingerprint text MUST be printed to standard
output

### Requirement: Dungeon

The system SHALL generate a procedural dungeon layout for a given seed, describe its layout, verify entrance reachability, and render the floorplan as ascii.

#### Scenario: GenerateAndRenderDungeonFloorplan
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A dungeon layout seed
- **WHEN** The dungeon command is executed
- **THEN** A procedural floorplan SHALL be created, its structural description and graph connectivity printed,
and its ASCII representation MUST be rendered

### Requirement: Diagnose

The system SHALL profile pathfinding search failure costs and bucket simulation step costs across fight ticks to isolate worst-case tick latency.

#### Scenario: DiagnoseStepLatencyAndSearchFailures
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A request to diagnose simulation latency
- **WHEN** The diagnose command is executed
- **THEN** Search failure overhead SHALL be measured and step duration profiles for sample seeds MUST be
printed to standard output

### Requirement: Profile

The system SHALL profile boss positioning pressure and isolate pathfinding search cost distributions across encounter maps and dense random obstacle grids.

#### Scenario: PathfindingAndPressureProfiling
- **GIVEN** A request to profile pathfinding internals
- **WHEN** The profile command is executed
- **THEN** Boss position pressure profiles across seeds and pathfinding costs on encounter gully vs dense maps
SHALL be measured and printed

## Technical Notes

- **Dependencies**: WowRoguelike.Core, Bench, Content, Dump, Dungeon, SimState
