# Wowroguelike-game Specification

> Generated by openlore v1.2.0 on 2026-10-13 11:07

## Purpose

Parses raw text commands from standard input into shell requests and simulation commands against the
live world state.

## Requirements

> `src/WowRoguelike.Game/Program.fs`

### Requirement: ParseCommand

The system SHALL parses a single line of text input into a shellrequest option based on the current world state.

#### Scenario: EmptyCommandString
- **GIVEN** An empty or whitespace-only command string
- **WHEN** parse is invoked
- **THEN** None MUST be returned

#### Scenario: SpeedControlCommand
- **GIVEN** A command string 'speed 1.5'
- **WHEN** parse is invoked
- **THEN** Some (SetSpeed 1.5) MUST be returned

#### Scenario: EntityMoveCommand
- **GIVEN** A command string '1 move 10 5' where entity 1 exists
- **WHEN** parse is invoked
- **THEN** Some (Issue (MoveTo (EntityId 1, { X = 10; Y = 5 }))) MUST be returned

#### Scenario: EntityAbilityUseCommand
- **GIVEN** A command string '1 2 lesserheal' where entity 1 has an ability named 'Lesser Heal'
- **WHEN** parse is invoked
- **THEN** Some (Issue (UseAbility (EntityId 1, 'Lesser Heal', EntityId 2))) MUST be returned

### Requirement: NormalizeAbilityKey

The system SHALL converts an ability name into a lowercase, alphanumeric-only key for punctuation-free matching.

#### Scenario: NameWithSpacesAndPunctuation
- **GIVEN** An ability name 'Druid\'s Slumber'
- **WHEN** key is invoked
- **THEN** The returned string MUST be 'druidsslumber'

> `src/WowRoguelike.Game/Program.fs`

### Requirement: AdvanceSimulation

The system SHALL steps the simulation world forward by one tick, scheduling all pending user commands for the next tick.

#### Scenario: PendingCommandsQueued
- **GIVEN** Pending command kinds in the command queue
- **WHEN** advance is called
- **THEN** Commands MUST be scheduled with ApplyAt equal to world.Tick + 1 tick, executed via SimTick.step, and
the pending queue cleared

### Requirement: FlushLogs

The system SHALL flushes newly generated world log lines to standard output and trims the log if it exceeds the maximum size.

#### Scenario: NewLogsGenerated
- **GIVEN** The world log contains more lines than previously printed
- **WHEN** flushNewLogLines is called
- **THEN** Unprinted log lines MUST be printed to the console in chronological order

#### Scenario: LogExceedsMaximumSize
- **GIVEN** The total log lines exceed 2000
- **WHEN** flushNewLogLines is called
- **THEN** The world log MUST be truncated to 500 lines

### Requirement: PrintPartySummary

The system SHALL prints the status, roles, health, resources, and available abilities of all entities in the world to the console.

#### Scenario: PartySummaryRequested
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A world containing entities
- **WHEN** printParty is called
- **THEN** Formatted entity details including ID, name, role, HP, resources, and ability keys MUST be output to
Console

### Requirement: RunGame

The system SHALL initializes the game engine and launches the main game loop.

#### Scenario: LaunchApplication
- **GIVEN** The game application is executed from the command line
- **WHEN** main entry point is called
- **THEN** The game client SHALL initialize MonoGame desktop window and run the game loop
