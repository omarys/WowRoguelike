# Architecture Specification

> Generated by openlore v1.2.0 on 2026-10-13 11:07

## Purpose

This document describes the architectural patterns and structure of the system.

## Architecture Style

Monolithic modular architecture: organized across distinct domain boundaries (core simulation, game
presentation shell, and execution harness) within a unified F# codebase.

## Requirements

### Requirement: LayeredArchitecture

The system SHALL maintain separation between:
- Game Presentation Shell (wowroguelike-game) (Application bootstrapping, player input parsing, entity interpolation, and desktop rendering)
- Core Simulation Engine (wowroguelike-core) (Core game mechanics, discrete tick progression, procedural generation, combat/aura mechanics, and spatial algorithms)
- Simulation Harness & Diagnostics (wowroguelike-harness) (Headless CLI execution, benchmark measurement, automated autopilot runs, state serialization, and golden replay fingerprinting)

#### Scenario: LayerSeparation
- **GIVEN** a request from the presentation layer
- **WHEN** business logic is needed
- **THEN** the presentation layer delegates to the business layer
- **AND** direct database access from presentation is prohibited

### Requirement: SecurityModel

The system SHALL implement security via: Not applicable; no authentication or authorization mechanisms are evident in the provided analysis, as the system functions as a local desktop game and headless simulation harness.

#### Scenario: AuthenticatedAccess
- **GIVEN** an unauthenticated request
- **WHEN** accessing protected resources
- **THEN** access is denied

## Layer Structure

### Game Presentation Shell (wowroguelike-game)

**Purpose**: Application bootstrapping, player input parsing, entity interpolation, and desktop rendering
**Location**: `GameApp, RoguelikeGameRunner, ShellInputParser`

### Core Simulation Engine (wowroguelike-core)

**Purpose**: Core game mechanics, discrete tick progression, procedural generation, combat/aura mechanics, and spatial algorithms
**Location**: `SimState, SimTick, AuraService, Content, Dungeon, GridService, Path, TimeModule, RngService, Rng, MinHeap, Heap`

### Simulation Harness & Diagnostics (wowroguelike-harness)

**Purpose**: Headless CLI execution, benchmark measurement, automated autopilot runs, state serialization, and golden replay fingerprinting
**Location**: `Program, Bench, BenchModule, Dump`

## Data Flow

Input received via MonoGame runtime input or CLI ShellInputParser → passed to SimState and SimTick
for turn and tick progression → AuraService, Path, GridService, and RNG resolve combat, AI, and
spatial movement → simulation state output rendered to the MonoGame shell, formatted via Dump for
diagnostics, or emitted as CLI benchmark/golden replay telemetry (no database persistence is
evident).
