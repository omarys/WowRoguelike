# Architecture Specification

> Generated by openlore v1.2.0 on 2026-11-13 21:19

## Purpose

This document describes the architectural patterns and structure of the system.

## Architecture Style

Layered architecture organized across domain-specific boundaries: pre-processing scripts and asset
extraction tools feed into a deterministic core simulation engine, which is decoupled from
presentation and consumed independently by a desktop client (MonoGame) and headless simulation/story
harnesses.

## Requirements

### Requirement: LayeredArchitecture

The system SHALL maintain separation between:
- Core Simulation (wowroguelike-core) (Deterministic game rules, combat resolution, grid-based pathfinding, party AI, and spatial state management)
- Presentation & Client (wowroguelike-game) (Desktop graphical presentation, sprite/tile rendering, camera tracking, and user interaction)
- Simulation Harness & Benchmarking (wowroguelike-harness) (Headless CLI execution, batch statistical runs, state fingerprint serialization, and performance profiling)
- Narrative Engine (wowroguelike-story) (Branching story scripting, dialogue resolution, quest tracking, and encounter boundary triggers)
- Asset & Map Processing (tools) (Extraction, background separation, slicing, and normalization of map grids and sprite tilesets)
- Verification & Content Scripts (scripts) (Validation and diffing of ability progression tables, level bands, and authored content definitions)

#### Scenario: LayerSeparation
- **GIVEN** a request from the presentation layer
- **WHEN** business logic is needed
- **THEN** the presentation layer delegates to the business layer
- **AND** direct database access from presentation is prohibited

### Requirement: SecurityModel

The system SHALL implement security via: No client authentication, user access control, or transport security mechanisms are implemented; the application executes locally as a standalone game client and CLI simulation harness, with execution credentials strictly scoped to external OpenWiki repository maintenance automation.

#### Scenario: AuthenticatedAccess
- **GIVEN** an unauthenticated request
- **WHEN** accessing protected resources
- **THEN** access is denied

## Layer Structure

### Core Simulation (wowroguelike-core)

**Purpose**: Deterministic game rules, combat resolution, grid-based pathfinding, party AI, and spatial state management
**Location**: `SimTickService, SimCombatService, SimStateService, PartyAiService, PathfindingService, DungeonGenerator, RngService`

### Presentation & Client (wowroguelike-game)

**Purpose**: Desktop graphical presentation, sprite/tile rendering, camera tracking, and user interaction
**Location**: `GameApplication, RoguelikeGame, Menu, Font5x7`

### Simulation Harness & Benchmarking (wowroguelike-harness)

**Purpose**: Headless CLI execution, batch statistical runs, state fingerprint serialization, and performance profiling
**Location**: `SimulationHarness, Program, BenchService, DumpService, AttributionService`

### Narrative Engine (wowroguelike-story)

**Purpose**: Branching story scripting, dialogue resolution, quest tracking, and encounter boundary triggers
**Location**: `StoryRunner, WailingCavernsStory`

### Asset & Map Processing (tools)

**Purpose**: Extraction, background separation, slicing, and normalization of map grids and sprite tilesets
**Location**: `WcMapExtractor, ScarletMonasteryMapExtractor, TilesetSlicer, DungeonAssetSlicer`

### Verification & Content Scripts (scripts)

**Purpose**: Validation and diffing of ability progression tables, level bands, and authored content definitions
**Location**: `RankVerifier, RankDiff, BandTotals`

## Data Flow

User inputs or CLI arguments enter via the Desktop Game or Simulation Harness → commands are parsed
and dispatched to SimTickService and PartyAiService → SimCombatService resolves deterministic 20Hz
ticks using SplitMix64 RNG, Chebyshev grid distances, and A*/Dijkstra pathfinding over immutable
SimState → combat events trigger StoryRunner narrative boundaries and are aggregated by
AttributionService/DumpService into canonical text diffs and replay fingerprints (no traditional
database persistence observed).
