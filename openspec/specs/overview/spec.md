## Purpose

A World of Warcraft-themed roguelike game and simulation engine featuring party combat, threat
mechanics, and procedural dungeon exploration. It enables deterministic tactical combat resolution,
role-based party AI, and narrative-driven dungeon encounters through classic instances. The platform
also provides headless execution fixtures, balance benchmarking, and automated asset and content
verification tooling.

## Domains

This system is organized into the following domains:

| Domain | Description | Spec |

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- Deterministic 20Hz simulation loop using splitmix64 PRNG with partitioned generation and combat streams to guarantee bit-exact replayability
- Strict decoupling of pure functional simulation logic (wowroguelike-core) from graphical presentation (MonoGame) to support headless testing and batch Monte Carlo simulation
- Separation of pure state transition queries (SimState) from combat resolution (SimCombat) and tick scheduling (SimTick)
- Array-backed binary min-heap with parallel priority and value storage to eliminate per-element tuple allocations during A* pathfinding
- Step-by-step narrative interpretation via Ink with pause boundaries at interactive player choices, quest completions, and combat encounters
- Offline image processing toolchain to convert raster dungeon maps into traversable discrete tile grids

## Technical Notes

- **Architecture Style**: Layered architecture organized across domain-specific boundaries: pre-processing scripts and asset extraction tools feed into a deterministic core simulation engine, which is decoupled from presentation and consumed independently by a desktop client (MonoGame) and headless simulation/story harnesses.
- **Security Model**: No client authentication, user access control, or transport security mechanisms are implemented; the application executes locally as a standalone game client and CLI simulation harness, with execution credentials strictly scoped to external OpenWiki repository maintenance automation.
- **External Integrations**: MonoGame Framework (desktop client rendering and runtime lifecycle), Ink Story Engine (narrative script parsing and interactive execution), OpenWiki (automated documentation workflows and repository pull requests)
